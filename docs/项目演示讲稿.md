# 项目演示讲稿（建议 6–8 分钟）

## 1. 问题与范围（约 40 秒）

我们的系统将 MovieLens 中分散的电影、类型和标签整理成图谱。用户可以先查找电影，再探索它的关系，最后看到带有明确理由的相似电影。第一版只使用类型和标签，不加入演员、导演、评分或用户画像。

## 2. 数据与图谱（约 60 秒）

原始数据有 9,742 部电影。清洗后保留 19 个类型、1,475 个标签，形成 22,050 条类型关系和 3,574 条标签关系。电影以 movieId 唯一定位，不能把名称当主键，因为源数据有五组完全重名电影。

说明三元组：`Toy Story (1995) — IN_GENRE → Animation`。电影和类型是实体，“属于类型”是关系。`HAS_TAG` 连接电影和标签。标签规范化后按电影去重，避免重复用户记录重复加分。

## 3. 系统操作（约 3 分钟）

1. 双击 start.bat，打开应用。展示左侧检索和上方真实数据统计。
2. 搜索 `Toy Story`，选择 movieId=1。展示标题、年份、类型和电影标签。
3. 解释推荐首项 Toy Story 2：五个共享类型、共同标签 pixar，所以分数为 6。展示第二项 The Lego Movie 同样为 6，但共享标签是 fun。理由全部由数据交集生成。
4. 滚动至局部图谱，点击 Animation 节点，展示关联电影列表，再选择其中一部电影。点击电影节点也能切换中心。调节关联数量以说明不一次绘制全部图谱。
5. 搜索 `Emma (1996)`，看到两个不同 ID 的同名结果。分别可独立选择。
6. 搜索无效名称，展示友好提示。用 `?movie=4` 打开无标签电影，在标签页说明此时只按类型推荐。
7. 切换数据概览，展示真实类型分布。后台 `/docs` 展示前后端接口分离。

## 4. 方法与验证（约 60 秒）

评分是共同类型数加共同标签数，取前五；同分按 movieId 升序保证稳定。本次将 Neo4j 中全部 9,742 部电影和原始 CSV 做独立比对，另随机抽查二十部 API 结果。推荐测试用独立集合运算计算全部候选，核对二十三组推荐。重复导入也通过幂等性检查。

这些是功能和一致性验收，不是用户满意度实验。我们没有用户画像，也没有测量预测评分准确率。

## 5. 局限与扩展（约 40 秒）

8,170 部电影没有标签，很多推荐主要由类型决定，容易同分。数据是 2018 年的开发快照，标签可能有主观性。后续可以研究标签权重、语义归并以及图嵌入链接预测，但新增模型必须有独立训练和评价，不能将本系统称为已经实现 TransE。
